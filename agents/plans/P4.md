## Algorithm overview

P4 is a local, spatially predictive post-processing algorithm. Like KLIP, it uses PCA to control a low-rank model, but
the model and its training data are different:

- KLIP treats the pixels in a reduction region as variables and constructs a reference-image basis for that region.
- P4 predicts one detector pixel at a time from nearby pixels in the same frame. It learns the prediction
  coefficients from the full time sequence, then applies the prediction to every frame.

For each annular search region and each search pixel `p` in that region, the prototype performs the following steps.

### 1. Construct a local optimization region

The search region (SR) is the set of pixels whose time series will be predicted. In the prototype it is a complete
annulus bounded by `srPixInner` and `srPixOuter`.

For each search pixel, an optimization region (OR) is placed around that pixel. The OR is an annular wedge described
by:

- an inward radial extent;
- an outward radial extent;
- an azimuthal half-width specified as arc length in pixels and capped by a maximum half-angle; and
- a circular central exclusion with radius `psfRad`.

The central exclusion is the essential signal-protection mechanism: pixels at the expected PSF location are withheld
from the predictors so the fit cannot directly use the companion being measured to predict itself.

The prototype constructs one canonical wedge on the positive-column side of the image, records the integer offsets of
its selected pixels, then rotates and radially translates those offsets to every search pixel. A cubic-convolution
kernel is precomputed for every `(search pixel, optimization pixel)` pair so the rotated OR can be sampled at
subpixel coordinates in each image. The half-pixel offsets in the prototype are part of this geometry and need to be
locked down by cardinal-direction and odd/even-size tests rather than simplified during the port.

### 2. Form a local temporal regression

Let there be `T` images and `K` selected optimization pixels for search pixel `p`. Define:

```text
y_p       T x 1   time series of the search pixel
X_p       T x K   interpolated OR pixel values for every image
A_p       K x K   X_p^T X_p
b_p       K x 1   X_p^T y_p
```

P4 eigendecomposes `A_p`. If `q_i` and `lambda_i` are its eigenvectors and eigenvalues, ordered from largest to
smallest, the truncated principal-component-regression coefficient vector is

```text
c_p(k) = sum(i=1..k) q_i q_i^T b_p / lambda_i.
```

The prototype obtains the same scaling by calling `mx::math::calcEigenVecs(..., normalize=true)`, which divides each
returned eigenvector by `sqrt(lambda_i)`. Its subsequent `E_k E_k^T b_p` is therefore a truncated pseudoinverse, not
merely an unscaled projection.

For each requested mode fraction, P4 predicts and subtracts the time series:

```text
yhat_p(k) = X_p c_p(k)
r_p(k)    = y_p - yhat_p(k).
```

The residual `r_p(k)` is written back to pixel `p` in one PSF-subtracted cube for that mode fraction. This repeats for
all search pixels and all configured annuli.

### 3. Perform the normal ADI final stages

Once the residual cubes are assembled, the prototype rotates every frame to the sky orientation, combines frames
with a sigma-clipped mean, and writes one final-image plane per mode fraction. In hciReduce these are already
configurable responsibilities of `ADIobservation` and `HCIobservation`; P4 should use that implementation rather than
retain the prototype's hard-coded `POSANG + 1.6`, sigma value, filenames, or paths.

### Scientific interpretation

The first implementation is an in-sample temporal regression: the same `T` frames determine the local coefficients
and receive the prediction. It is not leave-one-frame-out, and it does not perform KLIP's reference-frame exclusion by
field rotation. The mode truncation and central spatial exclusion control overfitting and astrophysical signal
leakage. Those semantics must remain explicit in the documentation and output provenance.

The prototype does not implicitly center predictor columns or fit an intercept. Its optional mean-image subtraction
occurs before the P4 calculation. The faithful hciReduce equivalent is the existing preprocessing configuration; P4
must not silently add a second centering convention.

## Prototype assessment

The prototype demonstrates the intended calculation, but the following parts should not be copied literally:

- Dataset paths, filename prefixes, `POSANG`, the `1.6` degree angle offset, region geometry, mode fractions, output
  names, sigma combination, CPU/GPU choice, and OpenMP thread count are hard-coded.
- A mode fraction is truncated to `int(fraction * min(T, K))`. This can produce zero modes or repeated mode counts,
  and the code does not define how either case should behave.
- `calcEigenVecs(..., normalize=true, check=false)` can divide by zero or a numerically negligible eigenvalue for a
  rank-deficient predictor matrix. A production implementation needs a scale-aware rank threshold and finite-result
  checks.
- Interpolation blocks are indexed without proving that the complete transform footprint lies inside the image. A
  search region near an image edge can therefore access an invalid block.
- The circular hole excludes OR sample centers, but a cubic interpolation footprint just outside the hole may still
  overlap pixels inside it. We must decide whether the scientific exclusion applies only to sample centers or to the
  entire interpolation support.
- `maskCircle()` itself applies its default half-pixel comparison buffer. The prototype's `psfRad=1.5` therefore
  excludes OR sample centers through a radius of 2.0 pixels; the configured-radius contract must state whether that
  legacy buffer is intentional.
- Only the P4 central hole participates in OR construction. The interaction with target masks, bad pixels, and NaNs
  is undefined.
- Search annuli can overlap, in which case later annuli overwrite earlier residuals. Parallelizing across overlapping
  regions would also introduce a write race.
- The accumulated timing variables are updated by multiple OpenMP threads without an active reduction or critical
  section.
- CUDA device selection performs a modulo by the device count without handling zero devices. The CPU/GPU separation
  is incomplete, the enabled coefficient calculation is CPU-only, and several device allocations are dead in that
  path.
- The large `allPredPix` scratch cube holds every frame, mode, and search pixel even though each completed residual
  vector can be written directly into its unique output pixels.
- FITS and numerical return values are not consistently checked, and some inactive error paths terminate the process
  directly.
- The prototype supports target-only ADI data. It does not define an RDI training model.

## Proposed hciReduce architecture

P4 should derive directly from `ADIobservation`, not from `KLIPreduction`. The two algorithms share observation
loading, fake injection, preprocessing, ADI metadata, derotation, combination, output, and provenance, but they do not
share their reduction state or worker mathematics.

### `common/P4PixelGrid.hpp`

A transform-templated geometry and sampling component, adapted from `postProcPixelGrid.hpp` and placed in
`mx::improc`.

Responsibilities:

- validate image dimensions, center, SR/OR geometry, and interpolation bounds;
- create radius/angle images for rectangular odd and even inputs;
- enumerate search pixels and the canonical masked optimization wedge;
- map the wedge to every search pixel;
- precompute interpolation coordinates/kernels; and
- sample an image at one mapped optimization point.

It should expose typed coordinate/kernel records through const accessors instead of public mutable vectors. Geometry
creation should be transactional: invalid input throws without leaving a partly valid grid. `resize()` and `region()`
should be separately testable, and stale kernels must be cleared whenever dimensions or geometry change.

### `common/P4PCA.hpp`

A pure numerical component with no FITS, application, derotation, or global observation state.

Its initial public operation should accept `X`, `y`, and an ordered list of retained mode counts and return one
residual column per count. It owns:

- selection and construction of the smaller Gram matrix: `X X^T` for `T <= K`, otherwise `X^T X` plus `X^T y`;
- eigenpair ordering and scale-aware rank validation;
- temporal-basis projection or the algebraically equivalent predictor-space truncated pseudoinverse;
- residual calculation; and
- finite/shape/error validation.

For `T <= K`, the implementation subtracts retained temporal modes directly as `u * (u.transpose() * y)`. For
`T > K`, it evaluates the predictor-space projection one eigenvector at a time without materializing a dense
projector. Both branches solve all `maxDOF = min(T,K)` eigenpairs and preserve the same rank and output contract.

Keeping this seam independent makes it possible to compare against a direct Eigen/SVD reference and later add a
different predictor without entangling geometry or the observation lifecycle. We should not expose a configurable
solver name until a second solver actually exists; the initial implementation is explicitly PCA.

The initial component is non-template and all-double. `P4Reduction` converts its float image samples at the boundary
and gives each worker a reusable `mx::math::syevrMem<double>`. `P4PCA::calculate()` replaces a caller-owned result
containing a `T x M` residual array, the exact numerical rank, and one explicit `rankSupported` or
`rankInsufficient` status per requested mode count. It solves all `maxDOF = min(T,K)` eigenpairs—even when the
largest requested count is smaller—because a partial solve cannot distinguish the exact rank from a lower bound.
The output has the basic exception guarantee: it is fully replaced on success and remains valid but unspecified if
calculation throws, avoiding a second `T x M` allocation at every search pixel.

### `common/P4Reduction.hpp` and `common/P4Reduction.cpp`

`P4Reduction<realT, derotFunctObj, verboseT>` derives from
`ADIobservation<realT, derotFunctObj, verboseT>` and orchestrates the reduction.

Responsibilities:

- register and load P4 configuration after the inherited HCI/ADI configuration;
- load pristine target inputs through the inherited file-list/read/preprocess lifecycle;
- reject unsupported RDI configuration in the initial version rather than silently ignoring it;
- validate region lists, fractions, masks, cube geometry, and output sizes before allocation;
- allocate one `m_psfsub` cube per configured mode fraction;
- build a `P4PixelGrid` per search annulus;
- assemble `X` and `y`, invoke `P4PCA`, and write residuals directly to unique output pixels;
- invoke the common ADI final-processing path; and
- append complete P4 configuration and per-region realized mode counts to FITS provenance.

The initial implementation statically requires float image storage, fixes its grid to `P4PixelGridf`, and calls the
non-template all-double `P4PCA`. Non-trivial definitions live in `P4Reduction.cpp`; the supported production
specialization is explicitly instantiated there and declared `extern` in the header.

## Resolved implementation contracts

The answers above establish the following initial-release behavior.

### Modes and numerical rank

- Mode fractions are finite, strictly increasing, and in `(0, 1]`.
- Each annulus uses `maxDOF = min(T, K)` and `floor(fraction * maxDOF)`. A zero realized count or duplicate realized
  count within an annulus is a configuration error.
- Numerical rank is the number of finite eigenvalues satisfying
  `lambda > p4.rankTolerance * lambdaMax`. A nonpositive `lambdaMax` means rank zero.
- Requested counts are never clamped to numerical rank. If a count exceeds a search pixel's rank, only that pixel's
  complete `T`-sample residual in that output plane is quiet NaN. Rank-supported lower-count planes remain valid.
- Eigensolver failure is an exception, not a rank-invalid result. Rank insufficiency instead produces unconditional,
  aggregated warnings and invalid-pixel counts in diagnostics/provenance without flooding stderr once per pixel.

### Regression, regions, and edges

- P4 is the prototype's in-sample temporal regression, formed from the smaller `min(T,K)` Gram matrix and a CPU
  LAPACK eigendecomposition. It adds no implicit centering and no intercept.
- The initial search regions are full, sorted, non-overlapping annuli. Every processed output pixel has exactly one
  owner.
- Region construction fails before reduction if any search pixel or any mapped OR sample lacks its complete nominal
  interpolation footprint. ORs are not clipped or partially modeled.
- Both `sampleCenter` and `kernelSupport` central-exclusion policies are implemented as explicit configuration values
  so the AF Lep/NACO comparison can measure their effect. No silent policy selection is allowed in the initial
  comparison implementation.

### Masks, invalid values, and unsupported pixels

- The common input mask excludes masked target pixels and must also prevent every P4 predictor from consuming masked
  detector pixels. Mask support is enforced independently of whether preprocessing multiplies data by the mask.
- Nonfinite values in an individual input image are a hard data-quality error. The pristine loaded cube is scanned
  before preprocessing, and the working cube is scanned afterward so preprocessing cannot hide or introduce them.
- `P4PCA` rejects nonfinite `X` or `y`; rank insufficiency is the only numerical condition that intentionally creates
  NaN residuals.
- Residual cubes carry an explicit validity/ownership mask. Unsupported pixels are persisted as quiet NaN, never
  ambiguous zero, and cannot contribute to final combination.

### Scope, diagnostics, and validation data

- The first release is target-only ADI and rejects configured RDI input.
- CPU LAPACK is implemented first and parallelism is over search pixels with thread-local workspaces. There is no
  initial CUDA path.
- Diagnostics are opt-in and cover ownership/validity, the canonical OR, `K`/DOF/rank/retained counts, invalid counts,
  and timings. Enabling them cannot alter numerical output.
- The first real-data golden reference is the public AF Lep/NACO example used by `afLepbNaco.cpp`, beginning with its
  klipReduce-preprocessed cube and preserving the preprocessing provenance already recorded in its header.

### Phase 1 exclusion and mask subcontracts

The initial component API makes the prototype/comparison choices explicit without allowing per-pixel predictor-count
changes:

- `sampleCenter` and `kernelSupport` both compare against the same effective disk
  `psfRadius + exclusionRadiusBuffer`. A buffer of `0.5` reproduces the prototype's effective `maskCircle()` disk;
  `0.0` means the configured physical radius.
- `kernelSupport` conservatively tests the complete nominal interpolation `width x width` footprint, regardless of
  coefficients that happen to be zero at one subpixel phase. This matches the complete-footprint image-edge policy
  and avoids a second phase-dependent support contract. A canonical predictor column is removed annulus-wide if its
  mapped footprint overlaps the effective disk for any search pixel, so the surviving `K` is fixed and the disk is a
  true information barrier.
- `K` remains fixed within each annulus. A masked search pixel is invalid; if any mapped nominal predictor footprint
  touches the common mask, that entire local search-pixel fit is invalid with an explicit reason. Predictor columns
  are never silently removed per pixel.
- The optimization wedge includes both angular boundary rays symmetrically. Radial enumeration remains inclusive at
  the buffered inner radius and exclusive at the buffered outer radius. This explicit angular contract preserves the
  intended half-width symmetry and the AF Lep prototype's realized first-annulus predictor count (`K = 2235`)
  without depending on single-precision rounding at 180 degrees.

`p4.psfRadius` is positive in the initial release unless the comparison establishes a separately documented safe
zero-radius behavior; the target pixel may never enter its own predictor set.

`P4PCA` accepts an explicit finite, nonnegative rank tolerance and applies the literal strict relative threshold.
The `P4Reduction` configuration default and any narrower configuration-level upper bound must be selected before
Phase 4; the pure numerical component does not hide a default. With a zero tolerance, every eigenvalue returned as
positive is retained, including a roundoff-positive numerical null, so a nonzero tolerance is required when reliable

## Acceptance criteria

- `p4Reduce` performs one configured P4 reduction through the standard hciReduce input, preprocessing, ADI final, and
  output lifecycle without dataset-specific constants.
- P4 geometry and PCA regression are independently testable and documented, finite for rank-supported planes,
  deterministically NaN only for pixels/planes exceeding numerical rank, and deterministic across supported OpenMP
  thread counts.
- The central exclusion has an explicit tested information-boundary definition, and target/mask/edge policies never
  produce silent scientific holes or invalid interpolation.
- Every requested output plane maps to a documented mode fraction and records realized per-annulus mode/rank data.
- KLIP products and application behavior remain unchanged after shared-lifecycle extraction.
- The initial release rejects undefined RDI, overlap, edge, nonfinite-data, or backend cases rather than guessing;
  common-mask exclusions and rank insufficiency instead remain explicit in authoritative validity cubes.
- New P4 code reaches 100% executable-line and function coverage, all called mxlib APIs satisfy the 100% coverage
  gate, and normal/sanitizer/documentation/install checks pass.
- The selected real-data comparison reproduces the prototype within agreed tolerances, with every intentional
  difference documented.
